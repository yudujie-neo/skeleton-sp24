# Lab 08 中文提示

本实验要求完成基于哈希表的 `MyHashMap<K, V>`。可假设不会插入 `null` 键，且删除后无需缩容。

- 根据键的 `hashCode` 选择桶，并在桶内处理哈希冲突。
- 构造方法需支持默认参数、指定初始容量，以及同时指定初始容量和最大装载因子。
- 装载因子是“元素数 / 桶数”。超过阈值时必须扩容并重新分配元素；容量应按几何级数增长，避免性能测试超时。
- 必须通过 `createBucket()` 工厂方法创建每个桶，不要直接 `new` 某种桶结构。测试会重写该方法以替换桶类型。
- 只使用一个实例变量保存桶数组，否则检查底层数组长度的测试会失效。
- 键存在但值为 `null` 时，`containsKey` 仍应返回 `true`。
- `keySet()` 和 `remove()` 是可选部分；不实现时抛出 `UnsupportedOperationException`。

## 测试顺序

先通过 `TestMyHashMap`，再运行 `TestMyHashMapBuckets`。后者会用不同 `Collection` 实现作为桶。如果哈希冲突边界测试失败，可用调试器对比 Java `HashMap` 的行为，并检查自定义键的 `equals` 与 `hashCode`。

`InsertRandomSpeedTest`、`InsertInOrderSpeedTest` 和 `BucketsSpeedTest` 分别用于比较随机插入、顺序插入以及不同桶类型的性能。
